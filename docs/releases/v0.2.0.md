# v0.2.0

Torii Gateway's first release is a beta. It provides an OpenAI-compatible gateway,
a browser console, encrypted SQLite credentials, client keys and usage budgets,
provider discovery, and configurable smart routing with benchmark evidence.
Subscription access supports OpenAI Codex device/browser login and Nous API keys.

## Installation

Choose either a native binary or the Linux container image. This release contains
five gateway binaries, `SHA256SUMS`, and `CONTAINER_IMAGE.txt`.

### Native binary

Download your binary and `SHA256SUMS` from this release:

| System | Architecture | Asset |
| --- | --- | --- |
| Linux | x86-64 | `torii-gateway-linux-amd64` |
| Linux | ARM64 | `torii-gateway-linux-arm64` |
| macOS | Intel | `torii-gateway-darwin-amd64` |
| macOS | Apple Silicon | `torii-gateway-darwin-arm64` |
| Windows | x86-64 | `torii-gateway-windows-amd64.exe` |

On Linux, verify and prepare your download (replace the filename for ARM64):

```sh
sha256sum --ignore-missing -c SHA256SUMS
mkdir -p bin
cp torii-gateway-linux-amd64 bin/gateway
chmod 0755 bin/gateway
./bin/gateway version
```

On macOS, run `shasum -a 256 torii-gateway-darwin-arm64` (or the Intel filename)
and compare it with the matching line in `SHA256SUMS`. Copy that binary to
`bin/gateway` and run `chmod 0755 bin/gateway`. On Windows, use
`Get-FileHash torii-gateway-windows-amd64.exe -Algorithm SHA256`, compare it with
`SHA256SUMS`, and copy the binary to `bin/gateway.exe`. Stop if any hash differs.

For a fresh Linux/macOS installation, create private storage and a database
master key, then start the gateway:

```sh
umask 077
mkdir -p state secrets
openssl rand -hex 32 > secrets/torii_db_key
export TORII_DB_KEY_FILE="$PWD/secrets/torii_db_key"
./bin/gateway serve --database ./state/torii.db --listen 127.0.0.1:8080
```

Generate the key once and back it up separately. Preserve the same database and
key for every restart; losing the key prevents decryption of saved credentials.
For Windows key generation, PowerShell startup and service installation, follow
[Native installation](https://github.com/Apartment38/torii-gateway/blob/v0.2.0/docs/installation/native.md).

### Container image

The image supports Linux amd64 and arm64 and runs as UID/GID 65532.
`CONTAINER_IMAGE.txt` contains the immutable multi-platform image reference.
While the package is private, authenticate to GHCR with an account that has
package read access before pulling it.

On a rootless Linux Podman host, with the release files in your installation
directory:

```sh
umask 077
mkdir -p secrets
openssl rand -hex 32 > secrets/torii_db_key
podman secret create torii_db_key secrets/torii_db_key
podman volume create torii_gateway_database
podman run -d --name torii-gateway \
  -p 127.0.0.1:8080:8080 \
  -v torii_gateway_database:/data:Z \
  --secret torii_db_key,type=mount,target=torii_db_key,uid=65532,gid=65532,mode=0400 \
  -e TORII_DB_KEY_FILE=/run/secrets/torii_db_key \
  "$(cat CONTAINER_IMAGE.txt)"
podman logs torii-gateway
```

Back up the master key separately and retain the database volume. Docker,
Compose and other host permission options are covered in
[Container installation](https://github.com/Apartment38/torii-gateway/blob/v0.2.0/docs/installation/containers.md).

### Finish setup

1. Open <http://127.0.0.1:8080/>. For a noninteractive/container launch, enter the
   single-use setup code from the terminal/container logs; it expires in 30 minutes.
   An interactive native launch prompts for administrator setup in the terminal.
2. Choose an administrator username and a password of at least 12 characters.
   Save the inference API key when displayed; it is shown once.
3. Sign in, open **Providers**, and add a provider. A fresh database has none.
   Follow [Getting Started](https://github.com/Apartment38/torii-gateway/blob/v0.2.0/docs/getting-started.md)
   to configure a provider and connect your client.
4. Check health:

   ```sh
   curl --fail http://127.0.0.1:8080/healthz
   ```

Use HTTPS through a reverse proxy for remote access. Keep the database master
key private. See [Operations](https://github.com/Apartment38/torii-gateway/blob/v0.2.0/docs/guides/operations.md)
for deployment details.

## Beta limitations

Provider subscription eligibility and token scopes depend on the upstream
provider. Pricing and benchmark evidence can be incomplete; estimated costs are
not provider bills. Run one gateway per local data volume. Torii does not provide
built-in TLS or high-availability coordination.
